# 烽火守城 · 三国塔防（H5 v2.17）

竖屏 9:16 的三国题材守城塔防 + 抽卡养成。HTML5 游戏：战斗画面用 WebGL（PixiJS）渲染、不支持时自动退回 Canvas 2D，界面是网页 DOM；所有文件都在本地，不依赖网络。

## 怎么运行

- 直接双击 `index.html` 用浏览器打开即可。
- 或本地服务器（Windows，不需要 Node/Python）：
  ```
  powershell -ExecutionPolicy Bypass -File serve.ps1
  ```
  然后打开 http://localhost:8731 ，浏览器开发者工具切到手机竖屏尺寸看效果。

## 玩法循环

出征守城 → 掉落/结算金币和精铁 → 金币换招募令（或每日看广告领）→ 招募武将和兵器 → 升级 / 升星 / 凑羁绊 / 排站位；抽到的兵器装给武将，精铁强化兵器；多余的碎片炼成将魂给主力补星 → 打更高关卡；已通关的关卡每天可以扫荡

## 战斗画面：WebGL（PixiJS）+ 2D 兼容

- 战斗画面默认用 WebGL 渲染（`js/glview.js`，引擎是 PixiJS 7.4.2，放在 `js/lib/pixi.min.js`，本地文件、MIT 许可）。
  它只负责画：读 `battle.js` 的战斗状态，把背景、敌人、武将、技能、界面文字都用显卡画出来。
- 比 2D 多的效果：动态光照（场景压暗，灯笼、火焰、技能照亮周围）、发光特效的泛光、敌将阵亡和大招的冲击波扭曲、更多火星；贴图自动合批，敌人和粒子多了不卡。
- 自动退回：浏览器不支持 WebGL、绘制出错、显卡上下文丢失时，自动改用 `battle.js` 里原来的 Canvas 2D 画法，游戏照常能玩。
  帧率持续低于约 38 帧时，依次关掉泛光、光照。
- 手动切换：主城「设置 · 存档」→「战斗画面：高清（WebGL）/ 兼容（2D）」。
- 界面（主城、武将、招募、弹窗）仍是网页 DOM。要上微信 / 抖音小游戏还得把界面也搬进 PixiJS 或换引擎。
- 改画面时两边都要顾到：新特效先在 `glview.js` 里做，2D 那份保持能看就行。

- 都是 SIL Open Font License 1.1，可商用、可随游戏分发；许可全文在 `assets/fonts/*.OFL.txt`，原始字体在 `tools/fonts-src/`。
- **网页版（国内朋友测试用）**：https://wendao-game.github.io/buyi-sanguo/sanguo-td/ 。网站是从仓库的 **`gh-pages` 分支**发布的（不是 main；布衣三国的网页版在这个分支的根目录），所以代码合并进 main 之后网站不会自己更新。更新网页版：`python3 sanguo-td/tools/pages_build.py <gh-pages 检出目录>/sanguo-td` 把运行文件拷过去，再提交、推到 `gh-pages`（脚本开头有完整步骤）。
- **claude.ai 试玩页要公开分享时**：平台审核只认 JPEG / PNG / GIF / WebP 图片和常见音视频，字体文件、SVG、AVIF 都过不了。发布试玩页前跑 `python3 sanguo-td/tools/artifact_build.py`，它生成三个试玩页专用的文件顶替同名文件：`css/style.css`（去掉 @font-face）、`js/fontload.js`（字体数据放在脚本里，用 FontFace 接口注册；仓库里的同名文件是空的占位）、`js/lib/pixi.min.js`（去掉库里探测 AVIF / WebM 用的内嵌样本）；`assets/fonts/` 不发。面板四角的花纹原来是内嵌 SVG，已改成 `assets/ui/corner_*.png`。正式上线不需要这一步。
- **改了游戏里的文字（新武将名、新技能名等）之后**，在仓库根目录运行一次 `python3 sanguo-td/tools/build_fonts.py`（需要 `pip install fonttools brotli`）重新裁字；没运行也不会出错，新出现的字会退回系统字体。

## 常用调节项（js/data.js 的 CFG）

先看《数值规划.md》。**每次改完数值都跑一遍 `node tools/sim/check.js`**（两三分钟，检查技能、武将强度、阵容、推荐战力、进度五项）。常改的几项：

- `TICKET_PRICE` 金币兑换价、`LEVEL_COST` / `LEVEL_COST_POW` 升级花费、`LEVEL_REFUND` 重置等级返还比例、`REPLAY_COIN` 重复通关金币比例
- `WEAPON_SHARE` 招募时每一抽出兵器的概率、`WEAPON_MELT_VAL` 兵器熔成多少精铁、`WEAPON_UP` 强化花费、`WEAPON_OWNER_MUL` 专属加成、`stageIron()` 通关给多少精铁
- `SOUL_VALUE` 一片碎片炼成多少将魂、`SOUL_COST` 升星时顶一片碎片要多少将魂
- `AD_DAILY_LIMIT` 每日广告次数、`AD_REWARD` 每次广告奖励、`AD_SWEEP_DAILY` 每日广告扫荡次数、`AD_REVIVE_WALL` / `AD_REVIVE_SAFE` 看广告复活城池回多少城防、几秒不掉血
- `QUALITIES[].rate` 各品质概率、`PITY` 保底抽数、`PITY_Q` 保底给的品质、`TEN_GUARANTEE_Q` 十连保底品质
- `ENEMY_HP_SCALE` 整体难度、`WAVES` 每关波数、`COIN_DROP_RATE` 掉钱概率
- `ROCK_MAX` / `ROCK_CD` / `ROCK_DMG` 投石、`AIM_SLOW` 瞄准慢动作、`AWAKEN_STAR` 觉醒星级、`SWAP_DELAY` 局中换将后多久出手
- `CC_DECAY` / `CC_MIN` / `PUSH_DECAY` / `PUSH_MIN` 敌人的控制抗性（被控次数越多，控制越短）；`HEAL_DECAY` / `HEAL_MIN` 技能回复城防的递减
- `SWEEP_DAILY` / `SWEEP_MUL` 扫荡
- `SLOT_ROLES` 站位、`FACTION_BONDS` 阵营羁绊、`ELEMENT_BOND` 属性共鸣、`COMBOS` 缘分、`WEAPONS` 兵器表
- `STAGE_POWER` 每章战力预算（= 推荐战力）、`HP_PER_POWER` 敌人血量系数：模拟器校准出来的，战力到推荐值时挂机约三局赢两局；改法见《数值规划.md》第 7 节

## 屏幕适配和新手引导（v2.18）

- **特效细化**（只改高清画面，「兼容」2D 画面不变；数值不变）：
  - 顿帧 `battle.js` 的 `hitStop()`：大招起手 0.05 秒、暴击打中敌将或精英 0.045 秒、精英和攻城器械倒下 0.06 秒、敌将倒下 0.13 秒（之后接原来的慢镜头）。两次之间至少隔 0.3 秒，只在 `frame()` 里把时间放慢，不带画面的模拟不受影响。
  - 按攻击类型的粒子 `elemFx()`：火星往上飘、冰碴四溅、电火花、毒泡、风丝打旋（`part()` 的 `kind`，画法在 `glview.js` 的 `drawPart()`）。技能和大招命中迸 3 颗、暴击 5 颗，普攻三成概率迸 1 颗。
  - 特效贴图的动画曲线：放大先快后慢，没有淡入的特效出场先弹大一点再回落，淡出先慢后快；宽 110 以上的大特效外面再叠一层放大、转一点的淡影（只在泛光开着时）。
  - 伤害数字：一下打掉三成血以上的数字变大、带暖光；暴击打掉五成以上变橙色；暴击数字先往上蹦再慢慢落。
  - 泛光从 0.34 调到 0.36，放大招的半秒再亮一点（再高中间会糊成一片白）。
  - 地面残留 `residue()`：火烧过的地方飘余火，霜面上闪光，雷劈过的地方偶尔噼啪一下。只按时间画，不进逻辑。
  - 模拟里放满特效时每帧脚本耗时和改前一样（约 1.6 毫秒）；显卡开销要在真机上看，帧率低时原来的自动降级（先关泛光、再关光照）照样生效。

- **长屏手机**（比 9:16 长，现在大多数手机）：宽度铺满，`#app` 的高度按屏幕算（最长到 9:21.6），主城、武将、兵器、招募往下延伸铺满；战斗画面和战斗按钮固定 540×960 贴底，上面多出来的一截（CSS 变量 `--ext`）由 `#ext` 画战场背景镜像并压暗，和战斗画面顶上的亮度接上。代码在 `main.js` 的 `fit()` / `drawExt()`，样式在 `style.css` 末尾「屏幕适配」一节。
- **平板**（比 9:16 宽）：保持 540×960 居中，两边铺一层模糊、压暗的战场背景。
- **刘海 / 底部横条**：`env(safe-area-inset-*)` 换算成界面像素放进 `--safeT` / `--safeB`，顶栏和底部导航让开。
- **升级引导**：前 20 关里，阵容中有「金币够、等级低于关卡数」的武将时，「武将」按钮闪、主城弹一次提示（`lvup1`），上阵武将头像左下角标「升」；失败页和战力不足的提示里加了「升级武将」。

- **主城四个入口**：每日军饷、挂机军饷、每日试炼、城池科技（`ui.js` 的 `homeRow()`）。
- **挂机军饷**：不在线也攒，每小时 = 最高通关那一关的通关金币 × `CFG.IDLE.k`（0.1），最多 8 小时；攒满约 0.8 倍通关金币（每日军饷是 2 倍），故意给得少。可以看广告双倍。起点只往后走，改时间不多给（`idleInfo()` / `idleClaim()`）。
- **每日试炼**：`TRIALS` 八条规则按天轮换（魏、蜀、吴、群四个阵营试炼，急行军、铁甲连营、怒火燎原、孤城死守），通关第 5 关后开放。关卡比已通关的低 3 关；每天第一次赢给精铁、将魂、1 张招募令，金币只按掉落给一半，不推进关卡、不出奇遇。阵营试炼开打时自动换上该阵营最强阵容（原阵容存在 `trialBak`），打完、退出、重开游戏都会换回；局中也只能换同阵营的人。参数在 `CFG.TRIAL`。
- **无尽关难度词缀**：每层固定（`data.js` 的 `ENDLESS_AFFIX` / `endlessAffixes(n)`，按层数算，输了重打还是那几条），第 1–29 层一条、30–59 层两条、60 层起三条：急行、坚甲、锐锋、迅令、疲兵、残垣、迟滞、铁壁。主城敌情和开局横幅会显示。倍率和每日试炼共用 `battle.js` 的 `S.mods`（试炼时只用试炼规则）。无尽关输了停在本层，「再战一次」重打同一层，不回退。

## 发布前要做的

0. **资源检查（每次打包上传前必跑）**：`node tools/sim/check.js`，第 6 项「资源」必须通过（单独跑是 `node tools/sim/econ.js`，一分钟内出结果）。它查的是无限金币、招募令、精铁、将魂这类漏洞：改手机时间刷每日、挂机、试炼，重复领奖，广告多发或超时后补发两次，升级重置、强化熔炼、炼化升星这些换算越转越多，NaN、字符串、Infinity 把货币弄坏，礼包码，保底，奇遇刷新，存档码。**新加任何发奖励的入口时，在 econ.js 里加一条对应的检查。**
   - 2026-11-18 审计后的修复：TapTap 里不再提供存档码（校验写在客户端、能伪造；有云存档和本机备份就够了），网页版读入存档码的进度永远不上排行榜（存档里的 `noRank`）；奇遇的掷骰结果存进存档，中途退出、重开拿到的还是同一个，一局打完才结掉（`encSettle()`）；`gain()` 只收正的有限数，读档时金币、招募令不是正的有限数一律清成 0；`buyTickets` 只认正整数。
   - **服务器时间**（2026-11-18）：TapTap 里每日军饷、扫荡、广告次数、试炼首胜、挂机都按服务器时间算（`platform.js` 的 `Clock`）。每次进游戏先上传一次云存档，上传完再取存档列表，读存档的 `modifiedTime`（服务器记的秒数）当作「现在」，之后用 `performance.now()` 往后推，改手机时间没用。每天按北京时间 0 点刷新（`save.js` 的 `dayNo`），改时区也提前不了。还没拿到服务器时间时（刚启动几秒、没网）用手机时间，但最多比上次确认过的服务器时间晚 36 小时：离线的正常玩家第二天照样能领，往后调时间一次最多多拿一两天，联网后就锁住。普通网页没有云存档接口，照旧用手机时间。主城「设置 · 存档」下面的云存档状态会显示「时间已校准 / 校准时间中」，**真机自测时看一眼是不是「时间已校准」**；确认能同步后，再去后台「云存档」页点「我已接入」（本服务无需手动开通）。
1. **广告位**：把后台申请的激励视频广告位 ID 填进 `js/data.js` 的 `CFG.AD_UNIT_ID`。留空时，在 TapTap / 抖音里不显示广告入口（网页版仍是 5 秒模拟广告）。
   点了广告 `CFG.AD_WAIT` 秒（默认 20）还没播出来就当这次没有广告，不会卡住。
2. **调试参数**：`?coins=5000&tickets=50&stage=12&all=1` 只在本机（`file://`、`localhost`、`127.0.0.1`）生效；正式网址和小游戏里一律忽略。
3. **云存档**：在 TapTap 开发者后台开通云存档。存档名是 `CFG.CLOUD_NAME`；进游戏时下载云端那份，与本机比较“累计获得金币”（`Save.earnedOf`：存档里的 `earned` 和「打到这一关的首通金币合计」取大的，老存档没有 earned 也不会输给空档），一样多再比关卡、武将数，最后比保存时间，取更新的那份；正在战斗（含结算页）时找到的更新存档先记下，回主城再换。之后有变化、不在战斗中时最多每 `CFG.CLOUD_EVERY` 秒上传一次。

6. **每日次数**（军饷、扫荡、广告）：按本地日期折算的「天序号」判断，只有比上次记录的那天更晚才重置（`save.js` 的 `isNewDay`）。把手机日期往前调不会重置，往后调了再调回来只是提前用掉那几天的份。

## 广告接入

`js/platform.js` 里的 `AdService.showRewarded()`：检测到 TapTap 小游戏（`tap.createRewardedVideoAd`）或抖音小游戏（`tt.…`）环境会走平台真实激励视频；
普通网页里是 5 秒倒计时的模拟广告。发奖逻辑和广告实现无关：招募令在 `save.js` 的 `adGrant()`，扫荡在 `sweepAdGrant()` + `sweep()`，
复活在 `battle.js` 的 `offerRevive()` / `revive()`（界面是 `ui.js` 的 `showRevive()`）。三个入口都先问 `AdService.available()`，平台里没填广告位 ID 就不显示。
模拟广告只在本机调试（`DEV`）和 `*.github.io` 的网页试玩版出现，别的地方没有 `tap` 就当没有广告。
等了 `CFG.AD_WAIT` 秒没播出来会先按「没有广告」处理；之后广告又播出来并看完的，招募令和扫荡照样补发（`showRewarded(late)` 的 `late`），复活过了时机不补。
播到一半出错（有的机型只来 onError 不来 onClose）按「没看完」处理，不会把后面的广告卡住。

TapTap 后台：开发者中心 → 游戏 → 商店 → 小游戏广告 → 申请开通（要先完成开发者认证和收款信息），建一个激励视频广告位，把 ID 填进 `CFG.AD_UNIT_ID`。
三个入口共用这一个广告位。后台直接开通只支持「H5 小游戏」等类型；登记成别的类型要走 TapADN，ID 来源不同。

## 换美术素材

把图片按约定文件名放进 `assets/`，并登记到 `assets/manifest.js`（`serve.ps1` 启动时自动生成），刷新即替换，没放的继续用程序画的：

- `assets/bg/battle.png`（1080×1920）战场背景
- `assets/heroes/<武将id>.png`（512×512 透明底，脚底中心在 256,440）武将立绘；`<武将id>_head.png` 头像可选
- `assets/enemies/<敌人id>.png`（同上）敌人

完整规格和武将 id 对照见 `美术素材规格.md`；模板在 http://localhost:8731/tools/art-guide.html 下载。
技能特效和界面图标目前仍是程序画的。
